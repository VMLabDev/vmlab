# C357. D3D9Ex ATI2 scratch volume texture

Wine 11.0's `d3d9ex.c:4585` checks that case 29 can create a 16×16×1
ATI2 volume texture with one mip level, usage zero and
`D3DPOOL_SCRATCH`. The baseline returned `D3DERR_INVALIDCALL`
(`0x8876086c`).

Windows uses system RAM for scratch resources. In the native x64
`d3d9.dll` examined on helios, the format-capability path calls
`CPixel::Register` for entries with `FORMATOP_PIXELSIZE` and a nonzero
private bit count. The call is at RVA `0x1c281`. The scratch branch in
`CBaseTexture::Validate` at RVA `0x3dda4` skips the adapter's format
validation, and the constructor calculates the size in the runtime.
Win3D had no ATI2 entry in its format table. The patch supplies the
BC5 size of 8 bits per pixel through `PrivateFormatBitCount` and sets
only `FORMATOP_PIXELSIZE`.
[Microsoft's FORMATOP reference](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/d3dumddi/ns-d3dumddi-_formatop).

Wine's standalone `d3d9_d3d9ex` ran on the Windows 11
`26100.1742.11#win3d` template on helios. The control package was built
from `2da659fd` and the candidate from `5695317b`. The installed UMD
hash matched the signed package in each run.

The AMD1 run installed both packages in sequence in one guest. The
candidate also removed line 4585 and executed the eight follow-up checks.
Display and window-focus failures varied across the two runs. The
candidate introduced no new failure lines or skip messages.
