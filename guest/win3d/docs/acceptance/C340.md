# C340. D3D9Ex fullscreen focus loss

The standalone Wine 11.0 `d3d9ex` program ran on the Windows 11
`26100.1742.11#win3d` template on helios with the 0.1.3 package built
by card #339 at `8a8c7d97`. The program used the guest's Windows D3D9
runtime with the Win3D driver. The installed UMD hash matched the
package on each run.

| GPU | Checks | Failures | Fullscreen failures | Skipped |
| --- | ---: | ---: | ---: | ---: |
| AMD1 (`renderD130`) | 2,379 | 11 | 5 | 41 |
| Nvidia2 (`renderD129`) | 2,379 | 72 | 12 | 41 |

The fullscreen assertions on AMD1 were at line 2949 with
`D3DCREATE_NOWINDOWCHANGES`, and at lines 3007 and 3100 with and without
that flag. All five check for `WM_DISPLAYCHANGE` before the test returns
to its message loop.

A separate AMD1 run traced the activation call and window messages
without changing the assertions. For the hidden-device-window case,
`SetForegroundWindow(GetDesktopWindow())` succeeded and cleared both
the foreground and focus windows. The desktop was already back at
1024×768 when the call returned. Both test windows received
`WM_ACTIVATEAPP` during the call and `WM_DISPLAYCHANGE` for 1024×768
after the assertion. The driver delegates the display mode change to
the Windows runtime through its mode-setting callback.

On Nvidia2, both iterations failed the checks at lines 2949, 2953, 2957,
2961, 3007 and 3100. In the instrumented run, a different window held
the foreground throughout the test's deactivation calls.
`SetForegroundWindow(GetDesktopWindow())` returned zero, and the
display remained at 800×600 through the check at line 2961. The test
windows did receive a 1024×768 notification later in each iteration.
The Nvidia2 run also reported foreground failures elsewhere in the
program.

The logs are in the `runs/amd2/evidence/` and `runs/nvidia/evidence/`
directories under `/home/vmlab/src/stc/card-340-work/` on helios. The
fullscreen assertion group remains open.
