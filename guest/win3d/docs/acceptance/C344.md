# C344. D3D9 cylindrical texture-coordinate interpolation

The [Mesa patch](../../patches/mesa/d3d9-interpolate-wrapped-coordinates.patch)
adjusts the selected components of `WRAP0` through `WRAP15` before
rasterization. For each line or triangle it places the seam in the
largest gap between the vertices' coordinates on the unit circle. The
pixel shader receives the interpolated coordinates folded back into the
unit interval. Draws use the render-state values restored by `Apply`.

The D3D9 probe renders the coordinates to a readback target. It checks
both sides of the seam for each component individually at `WRAP0`,
`WRAP8` and `WRAP15`. It clears each flag before applying the recorded
state block and checks the other components for ordinary interpolation.

The runs used the signed package from `c62f03b7` on helios with the
Windows 11 template `26100.1742.11#win3d` and the render server from the
vmlab-hv bundle. The win3d e2e passed all 12 checks on Nvidia2, including
the x64 and x86 D3D9 probes. The x64 D3D9 probe also passed on AMD1.

Wine 11.0 `stateblock` exercises the WRAP setters and state-block replay.
Card #253 had already cleared the WRAP setter failures. Wine's
[`visual` program](https://github.com/wine-mirror/wine/blob/wine-11.0/dlls/d3d9/tests/visual.c)
exercises sampler addressing and omits the WRAP render states. The pixel
readback probe provides the interpolation check.

additional failed assertions compared with C338. The `stateblock`
failure messages matched the remaining failures from card #253.
