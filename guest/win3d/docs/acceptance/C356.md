# C356. D3D9Ex display rotation

The Wine 11.0 `d3d9ex` program ran on the Windows 11
`26100.1742.11#win3d` template with vmlab-hv and Venus on helios.
The Win3D 0.1.3 package reused the C340 user-mode components and installed
miniport version `100.6.101.58115`. The running miniport's SHA-256 matched
the signed package.

| GPU | Driver | Checks | Failures | Rotation failures | Skipped |
| --- | --- | ---: | ---: | ---: | ---: |
| Nvidia2 (`renderD129`) | C340 baseline | 2,379 | 72 | 2 | 41 |
| Nvidia2 (`renderD129`) | C356 | 2,379 | 9 | 0 | 41 |

The baseline miniport excluded 180° from the video present network (VidPN)
path support and rejected that angle during path validation.
`ChangeDisplaySettingsExW` returned `DISP_CHANGE_FAILED` at line 573.
Win32 and D3D9Ex then reported the original orientation, failing line 608.
The patch advertises and accepts 180° for the single scanout, whose width
and height stay the same. [Baseline run](C340.md).

In a separate run with the same assertions and extra trace output,
`ChangeDisplaySettingsExW` returned success for the 180° request and for
restoration. `EnumDisplaySettingsExW` and `GetAdapterDisplayModeEx` both
reported 180° after the request and identity after restoration.

| Step | Win32 orientation | D3D9Ex orientation |
| --- | --- | --- |
| Before request | `DMDO_DEFAULT` (0) | |
| After 180° request | `DMDO_180` (2) | `D3DDISPLAYROTATION_180` (3) |
| After restoration | `DMDO_DEFAULT` (0) | `D3DDISPLAYROTATION_IDENTITY` (1) |

Each of the nine candidate failures also occurred in the earlier
Nvidia2 run. The unmodified program's output and the instrumented trace
are in `/home/vmlab/src/stc/card-356-work/nvidia/` as `candidate.txt`
and `candidate-trace.txt`.
