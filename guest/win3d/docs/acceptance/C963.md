# C963. The uncached memory type is hidden by default on an NVIDIA host GPU

Card #963 of the vmlab board. Card #136 measured Direct3D images with
64-byte holes on a laptop with an RTX 4060 (zeus), and clean images on two
boots with the host GPU setting `hide_uncached_memory = true`
([nvfb.md](../nvfb.md)). Card #963 made that the default where it is
needed: `hide_uncached_memory = "auto"`, on for a host GPU with the `nvidia`
kernel driver and off for every other driver. `true` and `false` still
decide alone.

This page records what the default costs on helios, where no hole was ever
seen: the Done checks, the adapter suite and the probe frame rates on the
second RTX 5090 (Nvidia2) with the filter on by default, against the same
runs of card #916 with the filter off (R7 and R8 of
[acceptance-2026-11.md](../../../../docs/agents/acceptance-2026-11.md#win3d-on-nvidia2-r7-to-r9-card-916)),
and the Done checks on AMD1, where the default leaves the filter off.

## Result

| Code | Run | Filter | Result | Baseline |
| --- | --- | --- | --- | --- |
| R1 | Done checks, `windows-11`, Nvidia2 | on (auto, `nvidia`) | 12 of 12 pass, all 20 rows pass | R7: the same 20 rows |
| R2 | Adapter suite, `windows-11`, Nvidia2 | on (auto, `nvidia`) | 24 pass, 5 fail, 0 not-run: the same five rows fail | R8: 24 pass, 5 fail, 0 not-run |
| R3 | Probe frame rates, `windows-11`, Nvidia2 | on (auto, `nvidia`) | 50.12 to 58.38 frames per second, each within 2.2 of R7, in two runs | R7: 50.06 to 58.22 |
| R4 | Done checks, `windows-11`, AMD1 | off (auto, `amdgpu`) | 12 of 12 pass, all 20 rows pass, probes 51.75 to 59.56 frames per second | R4 of card #886: the same 20 rows |

The default-on case costs nothing these runs can measure. No row changed
its verdict, and the frame rates differ from R7 by less than two runs with
the filter on differ from each other.

The proof that the default removes the holes is card #136's measurement on
zeus. helios cannot repeat it, because its images have no holes with the
filter off.

## The host log

The lab daemon writes the decision at every start of the VM
(`labd-<lab>.log` in vmlab's state directory):

```text
INFO win: host GPU `Nvidia2` (0000:05:00.0): hide_uncached_memory enabled (auto, kernel driver nvidia)
```

`vmlab status -v` shows `VMLAB_VK_HIDE_UNCACHED=1` in the VM's environment,
which R7's status did not have, and the filter layer writes one line for
each render context to `vmlab-hv.log`:

```text
vmlab-hide-uncached: memory type 2 (uncached) is hidden, guests use type 3 (cached)
```

On AMD1 the lab daemon wrote `hide_uncached_memory disabled (auto, kernel
driver amdgpu)` and the VM's environment had no `VMLAB_VK_HIDE_UNCACHED`.

### The `d3d9ex` row

`wine-d3d9_d3d9ex` failed one line set that R8 does not have. It failed
`d3d9ex.c:2049` and `2051` and did not fail `2915`. Both places test the
foreground window. At 2049 and 2051 (`test_lost_device`) `PresentEx` and
`CheckDeviceState` answer `S_OK` after `SetForegroundWindow` on the
desktop window, where `S_PRESENT_OCCLUDED` is expected. At 2915 the
foreground window is not the test's own.

A fifth hold ran the program alone three times with the filter on, and
then three times in the same lab with `hide_uncached_memory = false` (the
lab daemon logged `hide_uncached_memory disabled (explicit false)`, and the
VM had no `VMLAB_VK_HIDE_UNCACHED`):

| Run | Filter on (auto) | Filter off (`false`) |
| --- | --- | --- |
| 1 | 8 failures, the lines of R8, with 2915 | 9 failures, with 2049 and 2051 |
| 2 | 7 failures, neither 2915 nor 2049 and 2051 | 7 failures, neither |
| 3 | 7 failures, neither | 7 failures, neither |

The two lines appear with the filter off, and three runs with the filter
on do not have them. They depend on which window holds the foreground when
the program starts, as 2915 does: they are session-dependent failures of
draft D6, and not an effect of the filter. The other seven failures are
the same in all six runs and in R8.

## Xid

The kernel log is closed to the account `vmlab` on helios, as in card #916.
An Xid was watched by its symptom: no log of the VM had `Xid`,
`DEVICE_LOST` or `device lost` in any hold, every check ran to its verdict,
and `nvidia-smi` answered after every hold. The labs were destroyed at the
end of the third and the fifth hold, and the supervisor of the run was
stopped.
