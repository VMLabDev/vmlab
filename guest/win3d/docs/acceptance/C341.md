# C341. D3D9 W-buffer depth and wireframe

The D3D9 driver stores `D3DZB_USEW` and `D3DFILL_WIREFRAME` through
the normal render-state path, including when the runtime applies a state
block. In W-buffer mode the generated fragment shader recovers W from
the reciprocal clip W and maps it through the runtime's W and viewport
depth ranges. Explicit shader depth outputs retain precedence. Wireframe
selects line rasterization through the existing Gallium and Venus path.

The signed Win3D 0.1.3 package from `e572560b` was installed on fresh
clones of `windows-11@26100.1742.11#win3d` on helios. The installed x64 UMD
hash matched the package on both GPUs. Both VMs used the vmlab-hv bundle's
render server.

| GPU | Render node | Baseline Wine checks / failures | C341 Wine checks / failures | Render checks passed |
| --- | --- | --- | --- | --- |
| AMD1 | `renderD130` | 12,268 / 25 | 14,738 / 0 | 3 of 3 |
| Nvidia2 | `renderD129` | 12,268 / 25 | 14,738 / 0 | 3 of 3 |

The Wine rows used the same x64 `d3d9_stateblock.exe` as the baseline.
Both runs exited 0 with zero skips, todos and flaky checks. The setter
failures at line 1233 and the replay failures at line 297 cleared.

The render probe applied recorded state blocks before drawing. It placed
two triangles over the same pixels with opposite Z and W orderings. The
center read back green in Z-buffer mode and red in W-buffer mode.
With wireframe enabled the center stayed black, and 30 pixels sampled
along the horizontal edge were red on each GPU.

The Win3D e2e passed all 12 Done checks on AMD1 and also on Nvidia2.
The adapter run was scoped to the named Wine program. The probe source
and GPU evidence are in `card-341-work` under helios's
`/home/vmlab/src/stc`.
