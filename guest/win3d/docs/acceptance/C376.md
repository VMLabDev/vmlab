# C376. Wine D3D9 baseline on next

The baseline uses `next` at `0008d0c9336d31ad1baf5b84dd75c30c5486b814`
on helios, with vmlab-hv, Venus, and the Windows 11
`26100.1742.11#win3d` template. Mesa and the miniport were built from
that checkout and packaged as Win3D 0.1.3 with miniport version
`100.6.101.58115`. The package manifest records `8debe847`, the last
commit touching the Win3D subtree at that revision. Packaging reused the
Vulkan SDK and D3D12 outputs from the C374 workspace. Their build inputs
match the baseline revision. The host used the C341 vmlab and vmlab-hv
bundle.

Each Wine 11.0 program runs separately in the autologon user's desktop
session after the desktop setup reboot and the driver installation reboot.
The installed miniport and x64 user-mode driver hashes matched the signed
package. The test units set the host open-file limit to 65,536. The
earlier `d3d9_device` runs in B5 and B6 stopped when the hypervisor
exhausted the default limit. [Earlier adapter runs](../acceptance.md#baseline).

## Draft cards

**A1. Restore ATI1 texture creation and finish both Wine programs.**
`device.c:9759` reports `E_NOTIMPL` for ATI1N in the system-memory and
managed pools on both GPUs. The 60 failures per GPU are 25 2D and five
cube textures in each pool. The next ATI1N texture creation fails at
`device.c:9805`.
Wine then uses the failed texture result at line 9806 and raises an
access violation. In `visual.c:15637`, the Fetch4 test also sees
`E_NOTIMPL` from managed texture creation and uses the result at
line 15638. A separate AMD1 run added a trace of the format and return
value at line 15637. L8, L16, R16F and R32F succeeded. The 4×4 ATI1
texture returned `0x80004001`. The trace is in
`amd/evidence/visual-fetch4-trace.txt` under the evidence directory.
The earlier Nvidia2 Fetch4 precision check at line 15668 needs a
successful creation before it can run. [C359](C359.md).

Trace the DDI input pitch and slice pitch for ATI1 and compare them with
the BC4 layout in `D3D9TextureSubdata` (at least eight bytes per block
row for a 4×4 texture). The borrowed-storage change now
passes the runtime pitches through. Texture creation can return
`E_NOTIMPL` when the initial upload rejects a pitch below the
block-aligned minimum. The input pitch in the failing call still needs
measurement. Run `d3d9_visual` and `d3d9_device` through their summaries
on both GPUs, and verify that the Ex L8 upload at `d3d9ex.c:872` still
passes. [Borrowed-storage change](../../patches/mesa/d3d9-preserve-borrowed-system-memory-pitch.patch).

**A2. Resolve fullscreen notification and focus checks in the Wine
desktop.** Both GPUs missed five `WM_DISPLAYCHANGE` messages in `d3d9ex`
at lines 2949, 3007 and 3100, and five in `device` at lines
4248, 4319 and 4410. Repeat in a controlled foreground session and capture
activation, display mode changes and message delivery on both GPUs.
The earlier trace found a notification arriving after Wine checked and
a separate foreground-window conflict. [C340](C340.md).

**A3. Trace fullscreen device-window style restoration.** Each GPU failed
four `device` assertions at lines 5179, 5184, 5215 and 5220. The ordinary
and extended window styles differed from the expected values after
fullscreen transitions. Trace the styles and visibility around the
corresponding calls, then repeat those assertions on both GPUs.

**A4. Trace indexed draws after stream 0 is cleared.** At
`device.c:3238`, both GPUs returned `E_FAIL` with a valid index buffer and
vertex declaration after `DrawPrimitiveUP` cleared the stream source.
Trace the missing-stream handling in the indexed draw path. Check that
the draw returns success without changing the nearby invalid-call cases.

**A5. Match restricted Ex depth-stencil creation.** On both GPUs, case 2
returned `D3DERR_INVALIDCALL` at `d3d9ex.c:687` and left the surface
pointer null at line 705. Trace the runtime and driver calls for the
64×64 D24S8 surface with `D3DUSAGE_RESTRICTED_CONTENT`. Check the
expected result and output pointer on both GPUs.
[Earlier result](../acceptance.md#c343--d3d9ex-texture-upload-and-restricted-depth-stencil-creation).
