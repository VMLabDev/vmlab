# WSL2 audio

## Question
What path on WSL2, where WSLg serves PulseAudio?

## Answer
A second backend behind the same seam speaking the PulseAudio protocol (`libpulse-binding`), selected automatically when PULSE_SERVER points at WSLg's socket.

## Why
WSLg's socket speaks PulseAudio over RDP, and a distro-local PipeWire has no hardware sink (`notes/01`). Recommended option, accepted.

## Consequences
- Backend selection order needs defining: PipeWire when its socket is reachable, PulseAudio when PULSE_SERVER is set, else a null backend with a warning.
