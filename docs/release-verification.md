# Release verification

Releases contain `SHA256SUMS`, `SHA256SUMS.bundle` and `provenance.json`.
The manifest covers the CLI, guest bundle, hypervisor bundle and provenance.
The release job signs it with cosign using GitHub OIDC, with no stored signing
key. The bundle includes the certificate and transparency-log evidence.

Install cosign v2.6.1 or newer through a trusted package source before using
`install.sh`. The installer will not bootstrap its own verifier from an
unverified download. Older releases without a signature are refused.

To verify a downloaded manifest:

```sh
cosign verify-blob --bundle SHA256SUMS.bundle \
  --certificate-identity https://github.com/VMLabDev/vmlab/.github/workflows/ci.yml@refs/heads/main \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com SHA256SUMS
sha256sum --check SHA256SUMS
```

The provenance is a SLSA v1 statement generated by the release assembly job.
It records asset digests, the source commit, workflow and run URL. It is
authenticated by inclusion in the signed manifest. This is not a claim of
hermetic or independently verified builds, or a SLSA assurance level.

`just ci::release-dry-run` exercises manifest/provenance creation and installer
refusal paths offline. Its cosign contract stub checks the pinned identity
and issuer arguments, but does not prove cryptographic signing. Real OIDC
signing and immediate cosign verification run only in the main-branch release
job. No release or signing token is available to card-branch tests.
